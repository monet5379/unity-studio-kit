# Deepening

얕은 모듈 묶음을 깊게 만들 때 의존을 분류해요. 어휘는 [SKILL.md](../SKILL.md): **module**, **interface**, **seam**, **adapter**.

## 의존 분류

분류가 시임 너머 검증 방식을 정해요.

### 1. In-process

순수 계산, 메모리 상태, I/O 없음. 항상 깊게 만들 수 있어요. 모듈을 합치고 새 interface로 직접 검증. adapter 불필요.

### 2. Local-substitutable

테스트에 로컬 대체물이 있는 의존 (ScriptableObject 스텁, 인메모리 저장, 에디터 더블). 대체물이 있으면 깊게 만들 수 있어요. 시임은 모듈 **내부**. 외부 interface에 포트를 달지 않아요.

### 3. Engine-owned

Unity가 소유한 API (씬, 물리, Addressables, 시간). 포트를 씌우는 것은 어댑터가 **둘**(예: 런타임 Unity + 테스트 스텁)일 때만. 엔진을 가짜로 바꾸는 시임을 기본값으로 두지 않아요.

### 4. True external

통제하지 않는 쪽 (IAP, 넷코드, 네이티브 플러그인). 깊은 모듈은 주입된 포트로 받고, 테스트는 mock adapter. 벤더 원본은 수정하지 않아요 — 킷대로 **어댑터만 프로젝트에**.

## 시임 규율

- **어댑터 하나 = 가설 시임, 둘 = 실재.** 정당한 어댑터가 둘이 아니면 포트를 만들지 않아요
- **내부 시임 vs 외부 시임.** 깊은 모듈은 자기 테스트용 내부 시임을 가질 수 있어요. 테스트가 쓴다고 내부 시임을 외부 interface로 열지 않아요

## 검증: 겹겹이 쌓지 말고 교체

순수 도메인 C#(분류 1)에만 해당해요. MonoBehaviour 생명주기·PlayMode는 여기 해당하지 않아요.

- 얕은 모듈 단위 테스트는 깊은 모듈 interface 테스트가 생기면 폐기 후보
- 새 테스트는 깊은 모듈의 **interface**에서. interface가 테스트 표면
- 관찰 가능한 결과만. 내부 상태가 아님
- 내부 리팩터에 테스트가 깨지면 interface를 넘어 본 것

PlayMode·스모크·QA 스위트 추가는 사용자 요청 전까지 제안하지 않아요.
